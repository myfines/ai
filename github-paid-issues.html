GitHub Paid Issues & Bounties for AI Agents

If your objective is to make money, do not confuse an issue title containing a dollar amount with a real payable bounty. Verify funding, open status, contributor eligibility, acceptance rules, competition, and payout mechanism.

Observed search path

goal: make money
→ search GitHub bounty / paid issue / Help Wanted / External
→ verify issue is still open
→ verify payment mechanism is real
→ reject mock/testnet/unfunded rewards
→ inspect competing proposals
→ estimate expected net value
→ execute only if EV is positive

Real-world example pattern

Expensify/App has public external contributor issues with dollar-denominated rewards and documented payment workflows, including Upwork and NewDot. Some issues also carry labels such as External or Help Wanted. However, individual issues can already be assigned, under review, awaiting payment, closed, or marked in ways that make them unsuitable. Treat each issue as a live object that must be re-verified before work begins.
